Architectural Changes

Structural shifts to how the pipeline is composed, persisted, and orchestrated.
01
Parallel Agent 1a — Hypothesis Team with Voting
ArchitecturalLarge effortRisk: Med

What changes

Run N independent Agent 1a investigations in parallel (default N=3) with different system-prompt seeds — git history lens, dependency lens, error-trace lens. A new vote.sh stage merges their checkpoints by clustering on root_cause.file + line_range and selects by quorum + max confidence. Listed in potential_changes.md under "Agent Team".

Illustration

Three lensed investigations vote on the highest-quorum hypothesis before passing one consolidated checkpoint downstream.

02
SQLite Run Database for Cross-Run Analytics
ArchitecturalMedium effortRisk: Low

What changes

Add an append-only runs.db beside the JSONL audit trail. After every run, scripts/ingest_run.sh reads manifest.json, diagnosis.json, solution.json, cost_summary.json and inserts one row per run plus child rows per stage. Enables "avg cost per repo tier", "runs with confidence < 0.5 last week", "collector timeout rates". sqlite3 ships with git-bash and macOS — no new runtime dependency.

Illustration

Every completed run lands as structured rows in a single append-only file — queryable, exportable, zero new dependencies.

Plugin-Based Collector Discovery
ArchitecturalSmall effortRisk: Low

What changes

Today briefing.sh hard-codes calls to four collectors. Replace with a discovery loop that iterates collectors/*.sh and asks each for its meta (order, section, required_tools). Drop a logs.sh or k8s.sh into the folder and it joins the briefing — no orchestrator edit.

Illustration

Auto-discovery replaces explicit call-sites: collectors become drop-in plugins ordered by their own metadata.

04
Event-Driven Orchestrator State Machine
ArchitecturalLarge effortRisk: Med

What changes

Today orchestrator.sh is a long linear script. Refactor into an FSM where every stage produces typed events (STAGE_DONE, QUALITY_WEAK, SCHEMA_INVALID) on events.jsonl. A small dispatcher decides the next state — enabling resumable runs, cleaner branching, and a live feed for the future TUI.

Illustration

Stages emit typed events; a dispatcher reads the bus and selects the next state — branches and resumption become first-class.

05
Hash-Keyed Briefing Cache
ArchitecturalPerformanceSmall effortRisk: Low

What changes

Briefing is deterministic from (HEAD SHA, mentioned_files, error_strings). Cache briefing.md + errors.txt in .rca-mas/cache/briefing/{hash}/. A repeat run skips the four collector subprocesses entirely — invaluable for the eval harness (#7) which replays the same bugs hundreds of times.

Illustration

A deterministic cache key short-circuits the collector phase on repeat runs — minutes of CI time become tenths of a second.

06
Streaming Context Handoff Between Agents
ArchitecturalMedium effortRisk: Med

What changes

Today Agent 1b waits for Agent 1a to fully complete. Since Agent 1a already emits JSONL, the orchestrator can detect a FINAL FINDINGS block in-flight and start Agent 1b's pre-fetcher early. Net effect: 10–25% lower end-to-end latency on bugs where Agent 1a concludes in the first half of its budget.

Illustration

A live tail of Agent 1a's stream lets Agent 1b begin synthesis before 1a fully exits — the wait stage collapses.

Testing & Quality

07
Continuous Evaluation Harness
TestingMedium effortRisk: Low

What changes

A new tests/eval/ harness runs the 5 click bugs (and future fixtures) on every PR, computes diagnosis-vs-truth metrics (file match, line range overlap, confidence calibration, fix equivalence to upstream PR), and posts a markdown comment. Today the real-repo test only checks "did the pipeline finish?" — this catches silent quality regressions.

Illustration

Every PR runs the full fixture set and posts a regression-aware scorecard against the prior baseline.

Synthetic Bug Injection Framework
TestingLarge effortRisk: Low

What changes

The real-repo suite is bottlenecked on 5 hand-written click bugs. Add tests/synth/inject.sh that takes a clean repo + a recipe ("flip a boolean default at file:line") and produces a temp branch + a generated bug.md from the resulting test failure. Lets the eval harness scale to 50+ bugs without manual curation.

Confidence Calibration Tracking
TestingSmall effortRisk: Low

What changes

The pipeline emits confidence on every diagnosis.json, but nothing tracks whether 0.8 confidence corresponds to 80% accuracy. Add a calibration plot to the eval report: bucket runs by predicted confidence, compute empirical accuracy per bucket. Surfaces over- and under-confidence so RCA_CONFIDENCE_NOFX can be tuned from data, not gut feel.

A reliability diagram makes confidence honest: tune thresholds by where the dots fall, not by intuition.

Mutation Testing of Prompts
TestingMedium effortRisk: Low

What changes

Tests check the scripts, never the prompts. A tool that deletes one paragraph at a time from prompts/investigation.md, diagnosis.md, solution.md and re-runs the eval. If accuracy doesn't drop the paragraph is dead weight — prune. If it crashes the paragraph is load-bearing — annotate. Same idea as code mutation testing, applied to prompts.

Illustration

Deleting each paragraph one-at-a-time tells the team which prose pays its way and which is filler.

Batch Triage Mode
FeatureMedium effortRisk: Low

What changes

New flag: rca-mas.sh --triage bugs/ processes every *.md in a folder (or every open GitHub issue with label bug) in parallel and produces a single triage report ranking them by (confidence × impact-score) / fix-effort. A tech lead starts Monday with a prioritised queue, not 40 unread bugs.

Illustration

Parallel workers compress 40 bugs into a ranked, scored, single-page lineup the lead can act on in 30 seconds.

17
Diff-Aware Surgical Agent 2
FeatureMedium effortRisk: Med

What changes

When the bug is "new since <date>" — most of them — feed Agent 2 the git diff for the suspect file across that window as primary context, not the whole current file. Cuts input tokens 60–80% on focused regressions and biases the fix toward "revert the bad change" rather than "design a new one".

Illustration

Replacing the whole file with a focused diff window shrinks context, sharpens reasoning, and cuts cost two-thirds.

Adaptive Model Selector
PerformanceSmall effortRisk: Low

What changes

Today RCA_MODEL is one global. Make it per-agent and add an auto-tier mode: Haiku for Agent 1b synthesis, Sonnet for Agent 1a in <XS-tier repos, Opus only escalated when checkpoint confidence is below 0.5. Median cost drops ~35% on easy bugs while hard bugs still get the big model.

Illustration

A per-stage, per-tier matrix routes cheap calls to Haiku and reserves Opus for the moments that actually need it.

19
Run-Diff & Replay Tool
DXSmall effortRisk: Low

What changes

Two utilities. rca-mas diff A B side-by-sides two runs across every stage — turns, confidence, root cause, diff. rca-mas replay RUN_ID --from agent2 re-runs from any stage using cached prior artifacts. Today, regressing a prompt means re-running the whole 5-minute pipeline; with replay it's seconds.

Illustration

Diff turns two runs into one scorecard; replay turns a 9-minute regression test into 70 seconds.

20
Prompt Caching for Briefing & System Prompts
PerformanceSmall effortRisk: Low

What changes

Every agent re-sends the same briefing.md + static system prompt on every call (and across recovery/repair). Wire Claude prompt caching through scripts/claude_json.sh — mark system + briefing as cache-eligible. From the 2nd call onward (1b after 1a, Agent 2 after 1b, repair) cached tokens bill at 10%. Typical run: 30–50% input-cost cut.

Illustration

Marking the static prefix as cacheable bills repeat calls at one-tenth — a near-free input-cost reduction.
