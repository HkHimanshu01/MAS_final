FAQs
?Is this just prompting Claude?
No. The briefing phase is pure bash with zero LLM. It runs git blame, import tracing and error grep before any model call. Agent 1 gets pre-digested facts, not a raw repo. Agent 2 never sees the repo at all, only a schema-validated diagnosis. The pipeline is deterministic around the model calls, not inside them.
?What stops it from making up file paths or functions?
The diagnosis prompt explicitly forbids inventing files, commits, functions or evidence not in the checkpoint. Confidence is capped at 0.4 if evidence quality is weak. The output schema requires files_examined[] so there is an auditable evidence trail. It is not foolproof but it is structurally constrained.
?What if the diagnosis is wrong?
The confidence score surfaces it. Below threshold triggers a WEAK_EVIDENCE flag. Agent 2 is then told the evidence is weak and must reflect that in its own fix confidence. The final report shows confidence end to end. A reviewer who sees 0.42 confidence knows to treat it as a lead, not a conclusion.
?What is the context window strategy?
Each agent only receives the previous stage's output, not the full conversation history. This keeps each agent's context clean and prevents compounding errors across stages. Same principle as good retrieval. Do not give the model what it does not need.
?Why multiple agents instead of one big prompt?
Investigation and conclusion are different cognitive tasks with conflicting incentives. One agent running out of turns mid-conclusion will produce a cut-off or rushed output. Splitting into Agent 1a (many turns, free investigation) and Agent 1b (one turn, pure synthesis) means the conclusion always gets a dedicated budget.
?Can it miss the real cause if the chain runs through files Agent 1 did not surface?
Yes. If the real cause lives in a file with no recent commits, no import path and no error string linking it to the symptom, Agent 1 can miss it and Agent 2 will patch the wrong layer. Worktree validation catches this only if your test suite covers the affected behaviour. For deep multi-file cascades the developer review step is still doing real work. The system fails loudly when uncertain. It does not pretend to be infallible.
!
The honest caveat
The underlying reasoning is still Claude Sonnet. We are not claiming a smarter model. We are claiming a more reliable process. Structured inputs, validated outputs, explicit confidence scoring and a test-execution gate. The AI can still be wrong, but when it is wrong the system is designed to tell you rather than hide it.
